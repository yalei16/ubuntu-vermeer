# 安装指南（红米 K70 / POCO F6 Pro · vermeer）

> 本文只做「怎么做」；为什么这么改、以及和 sheng 的逐项差异见
> [移植对照.md](移植对照.md)。所有刷写都有风险，先看完第 0 步再动手。
>
> **最重要的一条（实测得出）**：K70 的设备树在 **vendor_boot** 里，不在 boot.img 里。
> 只刷 `boot.img` 的话 ABL 会把 Android 的设备树交给主线内核 → 大概率黑屏。
> 所以第 2 步的 `vendor_boot` **必须一起刷**。

## 0. 前置（缺一不可）

1. **解锁 BootLoader**。K70 国行解锁门槛很高（社区普遍走非官方渠道），
   pmOS/Nura 对同系机型的 wiki 页面也有明确记载。未解锁的机器下面全部无效。
2. **确认 A/B**：
   ```
   fastboot getvar current-slot        # 正常应输出 a 或 b
   ```
3. **备份原厂 boot / vendor_boot / dtbo**（唯一回滚底牌，务必留一份到 PC）：
   ```
   for p in boot vendor_boot dtbo; do
     adb shell su -c "dd if=/dev/block/by-name/${p}\$(getprop ro.boot.slot_suffix) of=/sdcard/stock-${p}.img"
     adb pull /sdcard/stock-${p}.img
   done
   ```
   也可以直接从官方线刷包里取同名文件。
4. **读一遍原厂镜像的参数**（不要照抄 sheng 的 header v0）：
   ```
   python3 scripts/host/12-analyze-bootimg.py stock-boot.img
   python3 scripts/host/12-analyze-bootimg.py stock-vendor_boot.img
   ```
   `boot_header_version` / `boot_pagesize` 填进 workflow；
   vendor_boot 打印出来的 `dtb_addr` 等由第 2 步的脚本自动读取，不用手填。

   实测参考（K70，HyperOS 13 / V816.0.11.0.UNKCNXM）：
   ```
   boot.img        : header v4, pagesize 4096, ramdisk 0, cmdline 空
   vendor_boot.img : header v4, pagesize 4096, dtb_size 3885971, dtb_addr 0x1f00000
   ```

## 1. 构建

Actions → **Build RootFS (Ubuntu / vermeer)** → Run workflow。建议第一次这样选：

| 输入 | 建议值 |
|---|---|
| desktop | `KDE Plasma`（勾 `plasma_mobile`）或 `Lomiri`（手机形态最贴合） |
| kernel_source | `custom_build` |
| boot_mode | `dual (linux)`（想和 Android 共存）或 `single (userdata)`（独占 userdata） |
| boot_header_version / boot_pagesize | 用第 0.4 步读出来的值（K70 = 4 / 4096） |
| append_dtb | `true`（先这样；vendor_boot 里也会带我们的 DTB，两条路都留） |
| install_modem_stack | `true`（不影响开机，先把地基铺好） |
| upload_artifacts | `true` |

编完在 run 页面下载：

- `rootfs-ubuntu-…` → `rootfs.img`
- `boot-ubuntu-…` → `boot.img`
- `kernel-custom-deb`（同一个 run 的 packages 作业）→ `linux-xiaomi-vermeer.deb`，**里面有 DTB**
- `kernel-custom-image` → `kernel-dtb_vermeer`（内核+DTB 拼接体，可跳过）

从内核 deb 里取出 DTB：

```
dpkg-deb -x linux-xiaomi-vermeer.deb kern
ls kern/boot/dtb-*.dtb        # 例如 kern/boot/dtb-7.3.0-rc6-sm8550+.dtb
```

## 2. 生成 vendor_boot（必须做）

```
scripts/host/13-make-vendor-boot.sh \
    --stock stock-vendor_boot.img \
    --dtb   kern/boot/dtb-7.3.0-rc6-sm8550+.dtb \
    --both
```

产物（`out/` 下）：

| 文件 | 说明 |
|---|---|
| `vendor_boot-vermeer-noramdisk.img` | **先试这个**：不带 vendor_ramdisk，内核没有 initramfs，直接 `root=PARTLABEL=` 挂 rootfs |
| `vendor_boot-vermeer-stockrd.img` | 备用：保留原厂 Android ramdisk（若 ABL 拒绝空 ramdisk 才用；它会让 Android 的 init 先跑，主线大概率起不来，需要自己塞 initramfs） |

脚本会用原厂镜像做模板（页大小、kernel/ramdisk/tags 地址、dtb_offset、
ramdisk table、bootconfig 全部照抄），只替换 DTB；已实测：用原厂 DTB 重打包，
产物与原厂文件**逐字节相同**（前 30,629,888 字节 sha1 一致）。

## 3. 分区（双系统才需要）

`sheng` 的流程对 K70 同样适用，但**会动 userdata**：先把 Android 里的资料全部备份出去。

在 TWRP 里（或用 `adb shell` + `parted`）：

```
# 看清楚再动手：确认要删的是 userdata
ls /dev/block/by-name/ | grep -E 'userdata|linux'
parted /dev/block/sda
  (parted) print
  (parted) rm  <userdata 分区号>
  (parted) mkpart userdata ext4 <原起点> <新终点>
  (parted) mkpart linux   ext4 <新起点> <磁盘末尾>
  (parted) name <新分区号> linux
  (parted) quit
mkfs.ext4 /dev/block/by-name/linux      # 可选：rootfs.img 会整体覆盖它
```

> 单系统（`single (userdata)`）不需要这一步：直接把 rootfs 刷进 userdata。

## 4. 刷写（一次做完，别反复重启）

```
# 4.1 先试跑 boot.img，不落盘（Xiaomi ABL 不一定支持，失败直接走 4.2）
fastboot boot boot.img

# 4.2 落盘：写到非当前槽，保证 Android 那一槽完好
fastboot flash boot_b        boot.img
fastboot flash vendor_boot_b out/vendor_boot-vermeer-noramdisk.img
fastboot flash linux         rootfs.img          # boot_mode=dual 时
fastboot set_active b
fastboot reboot
```

`boot_mode=single (userdata)` 时把第三行换成 `fastboot flash userdata rootfs.img`。

> 首次构建的 `boot.img` 里 cmdline 是 `root=PARTLABEL=linux`（或 `userdata`）。
> 分区名必须与 fstab/`PARTLABEL` 一致；用 `parted name` 设的分区名就是 PARTLABEL。

## 5. 首启判据（按优先级）

| 现象 | 含义 |
|---|---|
| splash 静止画面（不黑不花） | MDSS + 面板驱动已起，framebuffer 延续成功 |
| PC 出现 USB 网卡（RNDIS/NCM） | 内核 gadget 正常，可以 SSH 进去 |
| 屏幕进桌面 | 显示 + 输入链路都通了 |
| 触摸有响应 | gt9916 SPI 驱动载入 |
| `cat /sys/firmware/devicetree/base/model` → `Poco F6 Pro` | ABL 用的是我们的 DTB（vendor_boot 生效） |

如果**黑屏但 USB 有网**：说明内核起来了、DT 是 Android 的 → 检查是不是漏刷了
`vendor_boot_b`（这是最常见的一步漏掉）。

进系统后值得先看的几行：

```
dmesg | grep -iE "panel|dsi|msm|ufs"        # 显示与存储
ip link                                     # 网络
dmesg | grep -iE "remoteproc|ipa|qrtr"      # modem 链路（大概率还不通，见 README）
ls /sys/class/remoteproc/                   # 有 mpss/adsp 说明 remoteproc 起来了
```

## 6. 回滚

```
fastboot flash boot_b        stock-boot.img
fastboot flash vendor_boot_b stock-vendor_boot.img
# 或直接切回另一个槽
fastboot --set-active=other
fastboot reboot
```

## 7. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| `invalid boot image` | `boot_header_version` 与机型不符（照抄了 sheng 的 0） | 用第 0.4 步的实测值；v4 不需要 offset 参数 |
| 刷完黑屏但有 USB 网 | **漏刷 vendor_boot**（DT 还是 Android 的） | 刷 `vendor_boot-vermeer-noramdisk.img` 到 `vendor_boot_b` |
| 刷完直接回 fastboot | vendor_boot 被判非法（空 ramdisk 不被接受） | 换 `-stockrd` 变体；仍不行就在 initramfs 里自己做 `switch_root` |
| 内核起、根文件系统挂不上 | `root=PARTLABEL` 与分区名不一致 | 进 TWRP 用 `blkid` 看真实 PARTLABEL，或改用 `boot_mode=custom` |
| 亮屏两秒后重启 | 内核 panic | 用 `extra_cmdline` 加 `earlycon console=ttyMSM0,115200`，或读 pstore |
| 没有 WiFi | 固件路径不对 | 镜像里应有 `/usr/lib/firmware/ath12k/WCN7850/`（90-verify 会硬校验） |

# 安装指南（红米 K70 / POCO F6 Pro · vermeer）

> 本文只做「怎么做」；为什么这么改、以及和 sheng 的逐项差异见
> [移植对照.md](移植对照.md)。所有刷写都有风险，先看完第 0 步再动手。

## 0. 前置（缺一不可）

1. **解锁 BootLoader**。K70 国行解锁门槛很高（社区普遍走非官方渠道），
   pmOS/Nura 对同系机型的 wiki 页面也有明确记载。未解锁的机器下面全部无效。
2. **确认 A/B**：
   ```
   fastboot getvar current-slot        # 正常应输出 a 或 b
   ```
3. **备份原厂 boot / vendor_boot**（这是唯一的回滚底牌，务必留一份到 PC）：
   ```
   adb shell su -c 'dd if=/dev/block/by-name/boot$(getprop ro.boot.slot_suffix) of=/sdcard/stock-boot.img'
   adb pull /sdcard/stock-boot.img
   adb shell su -c 'dd if=/dev/block/by-name/vendor_boot$(getprop ro.boot.slot_suffix) of=/sdcard/stock-vendor_boot.img'
   adb pull /sdcard/stock-vendor_boot.img
   ```
   也可以直接从官方线刷包里取 `boot.img` / `vendor_boot.img`。
4. **读一遍原厂 boot.img 的参数**（不要照抄 sheng 的 header v0）：
   ```
   python3 scripts/host/12-analyze-bootimg.py stock-boot.img
   ```
   把打印出的 `boot_header_version` / `boot_pagesize` 填进 workflow 对应输入项。

## 1. 构建

Actions → **Build RootFS (Ubuntu / vermeer)** → Run workflow。建议第一次这样选：

| 输入 | 建议值 |
|---|---|
| desktop | `KDE Plasma`（勾 `plasma_mobile`）或 `Lomiri`（手机形态最贴合） |
| kernel_source | `custom_build` |
| boot_mode | `dual (linux)`（想和 Android 共存）或 `single (userdata)`（独占 userdata） |
| boot_header_version / boot_pagesize | 用第 0.4 步读出来的值（默认 4 / 4096） |
| install_modem_stack | `true`（不影响开机，先把地基铺好） |
| upload_artifacts | `true` |

编完在 run 页面下载两个 artifact：`rootfs-ubuntu-…`（含 `rootfs.img`）与
`boot-ubuntu-…`（含 `boot.img`）。构建日志里的 `[boot header v4]` 一行就是自检结果。

## 2. 分区（双系统才需要）

`sheng` 的流程对 K70 同样适用，但**会动 userdata**：先把 Android 里的资料全部备份出去。

在 TWRP 里（或用 `adb shell` + `parted`）：

```
# 看清楚再动手：确认要删的是 userdata
ls /dev/block/by-name/ | grep -E 'userdata|linux'
# 记下 userdata 的起止扇区，然后把它改小，后面的空间新建 linux 分区
parted /dev/block/sda
  (parted) print
  (parted) rm  <userdata 分区号>
  (parted) mkpart userdata ext4 <原起点> <新终点>
  (parted) mkpart linux   ext4 <新起点> <磁盘末尾>
  (parted) name <新分区号> linux
  (parted) quit
mkfs.ext4 /dev/block/by-name/linux      # 可选：本仓库的 rootfs.img 会整体覆盖它
```

> 只有单系统（`single (userdata)`）时不需要这一步：直接把 rootfs 刷进 userdata。

## 3. 刷写（一次做完，别反复重启）

```
# 3.1 先试跑，不落盘（Xiaomi ABL 不一定支持，失败就直接走 3.2）
fastboot boot boot.img

# 3.2 落盘：写到非当前槽，避免立刻覆盖 Android 的启动镜像
fastboot flash boot_b boot.img
fastboot flash linux rootfs.img          # boot_mode=dual 时
fastboot set_active b
fastboot reboot
```

`boot_mode=single (userdata)` 时改为：
```
fastboot flash boot_b boot.img
fastboot flash userdata rootfs.img
fastboot set_active b
fastboot reboot
```

> 首次构建的 `boot.img` 里 cmdline 是 `root=PARTLABEL=linux`（或 `userdata`）。
> 分区名必须与 fstab/`PARTLABEL` 一致；用 `parted name` 设的分区名就是 PARTLABEL。

## 4. 首启判据（按优先级）

| 现象 | 含义 |
|---|---|
| splash 静止画面（不黑不花） | MDSS + 面板驱动已起，framebuffer 延续成功 |
| PC 出现 USB 网卡（RNDIS/NCM） | 内核 gadget 正常，可以 SSH 进去 |
| 屏幕进桌面 | 显示 + 输入链路都通了 |
| 触摸有响应 | gt9916 SPI 驱动载入 |
| `cat /sys/firmware/devicetree/base/model` → `Poco F6 Pro` | ABL 用的是这棵树的 DTB |

进系统后值得先看的几行：

```
dmesg | grep -iE "panel|dsi|msm|ufs"        # 显示与存储
ip link                                     # 网络
dmesg | grep -iE "remoteproc|ipa|qrtr"      # modem 链路（大概率还不通，见 README）
ls /sys/class/remoteproc/                   # 有 mpss/adsp 说明 remoteproc 起来了
```

## 5. 回滚

```
# 回原厂启动镜像（最稳）
fastboot flash boot_b stock-boot.img
# 或直接切回另一个槽
fastboot --set-active=other
fastboot reboot
```

## 6. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| `invalid boot image` | `boot_header_version` 与机型不符（照抄了 sheng 的 0） | 用第 0.4 步的实测值；v4 不需要 offset 参数 |
| 刷完黑屏但有 USB 网 | 面板驱动没编进去 | 确认用的是 XEC 的树，且 `CONFIG_DRM_PANEL_XIAOMI_N1142020A=y`（构建日志会打印） |
| 内核起、根文件系统挂不上 | `root=PARTLABEL` 与分区名不一致 | 进 TWRP 用 `blkid` 看真实 PARTLABEL，或改用 `boot_mode=custom` |
| 亮屏两秒后重启 | 内核 panic | 用 `extra_cmdline` 加 `earlycon console=ttyMSM0,115200`，或读 pstore |
| 没有 WiFi | 固件路径不对 | 镜像里应有 `/usr/lib/firmware/ath12k/WCN7850/`（90-verify 会硬校验） |

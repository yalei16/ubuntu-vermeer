# 从 sheng（小米平板 6S Pro）移植到 vermeer（红米 K70 / POCO F6 Pro）

本文是这次移植的**依据与账本**：每个 sheng 组件对应到 vermeer 的什么、依据是什么、
哪些照搬、哪些替换、哪些删掉。所有"上游有什么"的结论都来自 2026-10-17 对仓库的实测
（GitHub API / 仓库文件内容），不是推测。

---

## 0. 三句话结论

1. **sheng 项目本身只是"脚手架"**：27 个文件、约 2700 行脚本，
   `Xiaomi-pad-6s-pro-Linux` 那棵树里只有文档；真正能复用的构建逻辑在
   `code002-2/ubuntu-sheng`（GitHub Actions + `scripts/host|in-chroot`），本仓库就是它的 fork。
2. **`k70移植方案.txt` 里"最大工作量"的两件事已经被别人做完了**：vermeer 的设备树与
   面板驱动早在 [Xlie-Electronic-Customs/linux](https://github.com/Xlie-Electronic-Customs/linux)
   里（`sm8550-xiaomi-vermeer.dts` 28,741 B + `drivers/gpu/drm/panel/panel-n11-42-02-0a-dsc.c`），
   固件也在 `linux-firmware-xiaomi-vermeer` 里。**不需要**从零写 DTS、也不需要写面板驱动。
3. 真正必须改的是四个"接口层"的东西：**内核来源与配置合并方式**、**boot.img 头版本**、
   **固件包目录结构**、**设备专属包（传感器/alsa/xiaomi-*）的取舍**；再加上设备形态
   （手机 vs 平板）的 rootfs 配置。这些本仓库已全部改完。

## 1. 组件对照表

| 组件 | sheng 的取值 | vermeer 的取值 | 处理方式 |
|---|---|---|---|
| 构建流水线 | `ubuntu-sheng`（rootfs.yml + _packages.yml + scripts/） | 同结构 | **照搬**，只改设备相关参数 |
| 内核树 | `ianchb/sm8550-mainline` @ `sheng-7.2.6` | `Xlie-Electronic-Customs/linux` @ `master`（7.3.0） | **替换**：实测 ianchb 那个仓库只有 `sheng-*` 分支，`sm8550-xiaomi-vermeer.dts` 返回 404 |
| 内核配置 | 仓库根一份完整的 `sm8550.config` 直接当 `.config` | 树内 `defconfig` + `sm8550.config` + `hardening.config` **片段**合并 | **替换**：该树没有 vermeer 的 defconfig，必须 `merge_config.sh` |
| 设备树 | `sm8550-xiaomi-sheng.dtb` | `sm8550-xiaomi-vermeer.dtb` | 替换名字，驱动随树自带 |
| 面板 / 触控 | sheng 自己的面板 + 手写笔 | `panel-n11-42-02-0a-dsc` + Goodix gt9916（都在树里） | 不用动 |
| 固件仓库 | `ianchb/sheng-firmware`（根目录就是固件根） | `XEC/linux-firmware-xiaomi-vermeer`（固件在 `xiaomi-vermeer/` 子目录） | **替换 + 修正路径**（否则驱动找不到） |
| boot.img 头 | header_version **0** + base/kernel_offset/tags_offset | header_version **4**（GKI），无 offset 字段 | **必须参数化**，照抄 sheng 会 `invalid boot image` |
| 启动镜像产物 | `Image.gz-dtb_sheng` | `Image.gz-dtb_vermeer`（Image.gz + DTB 拼接） | 改名；拼接顺序不变 |
| 预编译内核 | 上游每版 release 带 `boot_sheng_dualboot*.img` | 上游**没有**任何带 boot.img 的 release（只有 7.0-rc6 源码 tag） | prebuilt 降级为可选，默认 `custom_build` |
| 传感器 | `sheng-sensors`（SSC registry + udev） | 无对应物 | **删除**（K70 的 registry 还没人提取）；libssc/iio-sensor-proxy 仍构建，便于以后补 |
| 设备认证 | `sheng-devauth`（qtee） | 无 | **删除** |
| 音频 | `alsa-xiaomi-sheng`（WCD938X UCM2） | 主线 AudioReach 未通 | **删除**（装一份错的路由只会更难查） |
| 额外设备包 | `xiaomi-*`（快充/触控/笔/指纹，按 sheng 硬件写死） | 无 | **删除** |
| rootfs 定位 | `root=PARTLABEL=<分区>` + `x-systemd.growfs` | 相同 | 照搬（注意不是 PARTUUID） |
| 设备形态 | tablet / GridUnit 21 / Landscape | phone / GridUnit 18 / Portrait / `CHASSIS=handset` | 替换 |
| 分区与刷写流程 | TWRP + parted 新建分区 → `fastboot flash boot_b` → `set_active b` | 相同 | 照搬（K70 也是 A/B） |

## 2. 对《k70移植方案.txt》的逐条核查

| # | 原文说法 | 判定 | 依据 |
|---|---|---|---|
| 1 | 项目本质是 GitHub Actions 构建脚本集合，调 ianchb/sm8550-mainline + sheng-firmware + mkbootimg | ✅ 成立 | `ubuntu-sheng` 的 rootfs.yml / _packages.yml / scripts 结构 |
| 2 | K70 与 sheng 同 SM8550，内核编译流程/rootfs/boot 参数/fastboot 分区可直接复用 | ⚠️ 大体成立，**boot 参数不能复用** | sheng 是 header v0；K70 是 GKI v4，头结构不同 |
| 3 | 内核：如果 ianchb/sm8550-mainline 有 vermeer 分支就切过去，**没有就自己加 vermeer DTS** | ❌ 需要修正 | 该仓库只有 `sheng-*` 分支，且 `sm8550-xiaomi-vermeer.dts` 404；但 **XEC/linux 已有现成 vermeer 树与 DTS**，不用自己写 |
| 4 | 面板驱动主线大概率没有，是最大工作量，要做好逐行移植准备 | ❌ 不成立（对这棵树） | `panel-n11-42-02-0a-dsc.c` 已在该树；`sm8550.config` 里 `CONFIG_DRM_PANEL_XIAOMI_N1142020A=y` |
| 5 | 需要新建 `vermeer-firmware` 仓库、从原厂提取 WCN/QCA/触摸固件 | ⚠️ 已有现成的 | `XEC/linux-firmware-xiaomi-vermeer` 已含 `ath12k/WCN7850/*`、`qcom/sm8550/xiaomi/vermeer/*`（含 goodix 固件、a740_zap） |
| 6 | 固件包直接 `cp -a` 到 `/usr/lib/firmware` | ❌ 需要修正 | 上游固件在 `xiaomi-vermeer/` 子目录，直接铺会把路径变成 `/usr/lib/firmware/xiaomi-vermeer/ath12k/...`，驱动找不到 |
| 7 | `alsa-xiaomi-sheng` 改成 K70 的 codec | ⚠️ 暂不做 | 主线 AudioReach 连 voice/播放图都还没有设备侧 topology；先删包，别制造假象 |
| 8 | rootfs 脚本只改 hostname、fstab 的 PARTUUID | ⚠️ 部分成立 | fstab 用的是 **PARTLABEL**（不是 PARTUUID）；另外要改设备形态、删设备包 |
| 9 | 打包参数"完全照抄原厂：header_version 4、空 cmdline" | ✅ header v4 对；❌ cmdline **不能空** | 本方案没有 initramfs，必须 `root=PARTLABEL=<分区> rootwait`，否则内核找不到根 |
| 10 | 分区方案 TWRP+parted 删 userdata 新建 userdata+linux | ✅ 可用，但风险要讲清 | 会清空 userdata（Android 数据），必须先备份 |
| 11 | 推进顺序：先 USB 可用 → 点亮屏幕 → 触摸 → WiFi/BT → 电池/音频/传感器 | ✅ 顺序合理，但**前两阶段已经不用做** | 屏幕/触摸/3D/USB 在该内核上已可用（wiki: screen/touch/usbnet/3d = Y） |

## 4. 仍需在真机上确认的三件事

1. **boot.img 头参数**：默认 `4 / 4096` 是按 GKI 机型推的，但必须用
   `12-analyze-bootimg.py stock-boot.img` 读你手上那台机器的官方镜像来核对。
   这一步不需要设备，只要线刷包。
2. **分区名 / PARTLABEL**：`root=PARTLABEL=linux` 必须与 TWRP 里 `parted name` 设的一致，
   否则内核找不到根（现象：黑屏 + 无 USB，或反复进 fastboot）。
3. **WiFi**：上游 wiki 标 wifi=N，但固件（ath12k/WCN7850）已经在包里 ——
   属于页面滞后还是真不通，得实测 `dmesg | grep ath12k`。

## 5. 推进顺序（止损优先）

| 阶段 | 目标 | 现在能不能做 |
|---|---|---|
| A | 构建产物拿到手（不刷机） | ✅ 直接跑 workflow；`boot.img` 头会在构建里自检 |
| B | `fastboot boot` 试跑 → 成功再 `flash boot_b` | 需要真机 + 已解锁；失败就 `flash stock-boot` 回滚 |
| C | 进系统：屏幕/触摸/USB/SSH | 驱动都在树里，属"应该直接可用" |
| D | WiFi / 蓝牙实测 | 固件已就位 |
| E | 4G 数据 | 需要设备树补 `&ipa`（本仓库只做了内核配置与用户态，不够） |
| F | 音频 / 通话 | 属驱动开发（AudioReach voice subgraph），不是配置问题 —— **不要在这上面耗时间** |

**明确不要做的**：不要再为了"打开通话"去改内核配置或加 `q6voice` 这类补丁。
SM8550 的音频栈是 AudioReach，`q6voice` 是 msm8916-mainline 专属外挂，搬过来只会编不过或起来后无声。
